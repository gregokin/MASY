## D1 — existing checkout audit must remain names-only and schema-compatible

Reject adding checkpoint_registries or new native function calls/findings to contracts.run_native_audit. Keep its implementation, existing statuses/keys/filter/schema and existing CLI/source observer unchanged. Actual native registry capability probes belong ONLY in new runtime_worker.py. They are required there, and must call both actual registries unmodified, verify the required Dense binding is the real class, and refuse the old 2c60c73 missing-compact behavior before publishing a qualified runtime. The MASY table may require the new actual shared _native_ledger_types helper as a callable (source-backed new owning-SYRUP API), add required native SedimentLedgerState, and change CompactSedimentLedgerState to optional_class with both actual callers. That keeps older unpatched sources detectably incompatible without copying codec logic or changing old report semantics. Do not add new requirement kinds.

## D2 — stable runtime identity must exclude explicitly operational per-run paths

The design's full equality against environment_record/worker_env would fail every fresh verify because pycache_prefix, NUMBA_CACHE_DIR, MPLCONFIGDIR, HOME/request/run-directory paths change. Split stable identity from execution receipts. Strictly validate the actual per-run paths/flags/environment against the owned current run directory, then normalize ONLY those named operational paths for equality, or compare a closed explicit stable identity subset. Do not ignore arbitrary environment/metadata/compiled/source drift. Preserve raw actual paths in each execution receipt. Unselected shadowed MAPLE/SYRUP/MASY metadata is transparently recorded but not a reason to rebind or to invalidate an old lock merely because an upstream live checkout's egg-info disappears. Actual selected metadata, all relevant module origins/source digests, interpreter/dependency versions and relevant compiled identities remain strict. Prove two fresh verify runs against one explicit lock succeed without reading current source repositories.

## D3 — writable persistent default store and precise source/output separation

The proposed default /home/okin/MASY-runtime-store is outside the user's writable workspace. Use /home/okin/MASY/runs/runtime-store (already ignored) or an explicit /tmp store for tests. Permit a store under the wrapper repository only OUTSIDE its actual input scope: src/, tools/, pyproject.toml and .git are protected. Whole configured MAPLE/SYRUP roots, their ancestors/descendants, the interpreter/venv and distribution metadata remain protected; symlink aliases are checked. Do not allow store equality with the wrapper root or an ancestor. If sources are nested candidate roots, protect those actual roots. No blanket permission escalation for ordinary runtime preparation. No installation or auto-GC.

## D4 — source-object identity binds metadata generator and atomic publication implementation

The generic source object ID must bind the exact generator implementation/schema (or a fully specified overlay template) as well as source bytes. Otherwise changed generator code could collide with an older object's identical source ID but different expected overlay bytes. Metadata paths can be generated after determining the ID; avoid self-referential ID hashes. Verify exact overlay bytes/metadata/source fields before import. Reuse upstream public bundle functions for MAPLE, do not rename/generalize that owning tool. The parent may implement a small bounded atomic-no-replace helper for its own source/lock publication if needed, but no copied full bundle subsystem. Native bundle/hash/selection/metadata checks must actually run from the sealed SYRUP code.

## D5 — no speculative global/source/environment rewrites

Keep old sourceobs/importcheck/cli/config/report/clock implementations untouched. New runtime code can reuse their public helpers and add only bounded orchestration/sealing/metadata/worker code. New MASY pyproject static valid version and __version__ alignment are within scope. Do not add transport/schedule/state serialization/device support. The worker must reject foreign preloads/origins, preserve its ordinary sys.path search plus explicit sealed prefixes, and verify selected real metadata without monkeypatching discovery/resolvers. Native registry probes are class-dictionary operations only, no physical solver calls. Record imported CPU compiled identities with finite count/byte limits; do not claim GPU qualification or install a build backend.

## D6 — qualification/commit sequencing and evidence

Do not describe uncommitted candidates as current committed upstream. First run proportional source-native checkpoint tests and synthetic runtime tests. Codex can put independently accepted source candidates into the already-created authentic isolated Git branches for committed-source qualification, visibly recording candidate branch/root/commit and no current-main claim. Native source pair/overlay/registry runtime qualification must pass on those exact commits. Final actual-root qualification follows any authorized adoption, with concurrent-source checks; existing run/checkpoint sources are never rebound. Final task acceptance must distinguish source delivery, Dense checkpoint regression, remaining adapters, combined restart and performance limits. Keep all failed attempts and reports. Old documentation is historical; new docs/link pointers should accurately identify the new capability without silently rewriting old acceptance.

Proceed with two bounded implementation stages, one writer at a time per tree: A only owning-SYRUP allowed files, then B only MASY allowed files. Codex independently tests A while B is authored in the other tree. No confirmed high-severity design defect remains after D1-D6 corrections; actual implementation and end-to-end tests are still required.
