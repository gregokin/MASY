The revised Claude design is approved for bounded MASY-01 implementation, with the exact implementation requirements below. No physical compatibility or transport is accepted by this approval.

Design-review dispositions: (1) concrete isolated-file launcher resolves the import/bootstrap problem; (2) default current HEAD observation, stdlib pre-import guard and optional explicit expected lock resolve historical pin/bootstrap issues; (3) nonzero epoch, exact endpoint mapping and explicit contiguous intervals resolve uncounted gaps; (4) intended/native forcing evidence replaces rejection of ordinary float sums; (5) explicit field refusal replaces substring/date-string filtering; (6) failed native resolver is a concrete refusal, while API evidence remains visible; (7) only actual NumPy compiled identity and optional metadata avoid unnecessary imports; (8) physical/storage/adapter/restart limits remain explicit unqualified items, not invented impossibilities or mandatory upstream work.

Mandatory implementation details:

- Enumerate/hash the ACTUAL runtime package tree before importing upstream code, with explicit cache exclusions, no symlink files/directories, size/count limits and before/after consistency. Git's tracked list alone omits ignored/untracked runtime inputs. Detect extra ignored Python/runtime files before imports, while allowing unrelated out-of-scope cases and explicitly recorded generated distribution metadata. Include pyproject identity/hashes. All Git status calls disable optional locks and fsmonitor; cap/time-bound every subprocess.
- Clock commit_before must be <= native_start; commit_after <= native_end; both monotone. Sequential first start equals the stored epoch and every next start equals the preceding end. Preserve returned_elapsed separately and record any endpoint discrepancy, without correcting physics. Exact rational G(native) is reversible; data-only helper does not certify solver adapter mapping. Calendar fields including `absolute_start_s` and `fixed_calendar` are explicitly unsupported. Do not invent support for an `update` config field solely to satisfy a test: closed-schema unknown fields can be rejected; dated valid IDs/paths must work.
- Origins must resolve to the selected source observation (check concrete package directories/files, not a loose arbitrary ancestor). Post-audit re-observation runs after resolver/API failures as far as possible. Wrong/disappearing/dirty sources produce nonzero refusal before transport; no simulation entry point exists in this task.
- New run directory publication is exclusive; failed/oversized/incomplete reports never overwrite accepted outputs. Report both failure and original/source evidence honestly. Data inputs not read remain declared-unverified. Existing interpreter/environment and upstreams remain unchanged.
- No package snapshots or metadata repair implemented or claimed in MASY-01. Their proposal must allow a bounded MASY adapter/metadata overlay using unmodified upstream bundle mechanisms if suitable; upstream changes are required only if actually demonstrated necessary. No mandatory new human approval is invented for routine authorized development.
