# Private cold HOST and inert device-bed components

This module is private and exports no public API. The accepted cold-HOST component loads the native MAPLE physical codec with its original config/input capsule and an independently hashed companion. Its native bundle remains at the same path/inodes; companion-only relocation is allowed only with unchanged bytes and the original native files. It is not portable restart.

The appended `admit_device_bed_from_cold(cold, *, bed_limits)` is a separate, unqualified device-bed conversion. It requires genuine already-imported CuPy and exact bound bed limits. It never imports/selects a GPU backend, builds a fresh bed/runner, initializes a model, resets or commits native state, reroutes, runs an event, or consumes the cold ticket. A separately approved protected caller must establish actual current source/profile/native/process/device/UUID/PCI/resource authority and a new operation-specific grant. Identity-probe permission alone does not authorize this operation.

Only the six actual native bed holders move to the device: voxel column, active layer, water, pending ledger, committed topography and sediment availability. Actual `DeviceDenseBedOwner.from_device_bed` validates those resident arrays/time and makes private accepted/mirror copies. Local owner generation0 is recorded separately from saved bed/resource generations and native commit count/time; no saved stamp is rewritten.

All six remaining native physical fields stay in a closed inert HOST residual: genuinely empty flat mobile state, threshold modifiers, native time, prescribed raster vegetation, trajectory semantics and reconciliation baseline. Existing boundary policy requires the last two exactly `None`. The result is not a mixed-backend `SchedulerPhysicalState`, a scheduler, a runner or a continuation ticket. Soil, retained routing, ClockLedger, accounting/receipts/C-store adoption, production/windowed/dynamic/active-event support remain excluded. Every readiness/fit/qualified/restart flag stays `False`.

Before new hashes or uploads, existing bounded metadata/layout/original/native checks are reused. A closed walk admits exact contiguous native-order NumPy leaves and bounded owning ndarray base chains. It charges the full allocation behind views and rejects any residual/config/original retaining a bed holder, array, overlapping span or even a disjoint view of the same allocation. Unknown buffer exporters are refused; the loader/flags are not normalized. Native returned leaves are readonly, while reshape roots may remain writable through `.base`; caller-private quiescence and pre/post fingerprints remain required, not hostile-pointer security guarantees.

HOST DATA admission retains the existing conservative cold reservation, adds any excess backing allocation, and independently covers unique roots/metadata, one-leaf download+comparison, and two simultaneous 1 MiB native stream-hash blocks. The unchanged `_snapshot` streams files; it does not hold whole payload files. Companion `_read` chunks/join and bounded detached/planner metadata have a separate allowance. DATA is not RSS. The device's unchanged six-root/native/compare structural reservation must fit both the original bed-work and original device byte caps. Scratch slots remain DECLARED_UNMEASURED; library/JIT/reduction/pool/driver/whole-worker fit still requires a separate resource gate. The new whole-tree planner shares the original `max_leaves` ceiling across physical and original/config array visits; a tighter custom ceiling can refuse conversion without changing the old cold-load contract. Disjoint bed leaves may share a HOST allocation, charged fully once; sharing that root with residual/original/config is refused.

The six-field tree has exactly 23 distinct leaves; the actual nonmemoized mapper is used only after exact native holder/init/layout checks. Every converted leaf must be genuine same-device CuPy. The existing raw-copy helper must return exactly 23 verified leaves and B bytes. Converted references are dropped before final owner verification. Native c0–c4 snapshots and owner-private D2D/clone/packet counters are separate:

| Phase | Source-predicted successful accounting |
|---|---|
| Upload | native H2D23 transfers/B bytes |
| Raw readback | native D2H23 transfers/B bytes; raw uint8 comparison including signed zero |
| Owner construction | native31 scalar reads; one compact D2H packet46 float64 flags/368B; owner-private D2D46 arrays/2B |
| Final verify | one compact D2H packet23 flags/184B; no new D2D clone |

Thus native counted D2H is B + 552 bytes in 25 transfers for this component, not just domain B. The ledger's 17 boolean flag read is counted as one scalar synchronization and is not included in native D2H counters. Caller audit/export/load/observer traffic needs separate windows. These are source predictions, not measurements or a claim that counters capture all library/runtime traffic. No native counter is reset.

Failures retain cold evidence and record actual partial native snapshots. If the native owner constructor fails before returning an owner, its private partial D2D counts are unknown, not zero. Errors are detached outside the original exception handler so cause/context/traceback cannot retain partial device owners. `KeyboardInterrupt`/`SystemExit` keep their cancellation semantics. No global pool/cache clearing or rollback is assumed. Dropped allocations may remain in CuPy caches and must still count against pool/driver caps.

After successful conversion the protected caller retains both private tickets until its real post-check passes. It then calls the EXISTING `cold._release()` and drops other source references. The result retains no full physical/cold/source shell; HOST allocation-root and leaf weakrefs must demonstrate OWN release in a later genuine witness. Arbitrary external references are outside that lifetime claim. CuPy weakref support must be established, not assumed, when proving converted-source release.

The focused CPU checks use explicitly synthetic device-format metadata over genuine native CPU genesis/save/seal/cold load and preparation/negative/interface checks. They do not fabricate a genuine CuPy owner or qualify device restoration. Original 15 checks are preserved; 18 new checks are appended for a proposed 33-method Root-gated CPU group. One HOST backing-allocation control is bounded to 32 MiB before allocation; fixture cleanup drops cold references after each case. No transport/event is needed. Actual source/allocation/execution gates, a genuine positive export from Root159, and a fresh current source profile plus GPU witness remain required before any restoration claim. No numerical checks have been executed in this source-only candidate.
