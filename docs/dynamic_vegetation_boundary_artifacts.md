# Passive manual-vegetation boundary artifacts

This separate `dynamic_manual_dense_numpy_accepted_v1` profile prepares an inert
default-flat CPU owner from original inputs and actual native physical snapshots.
It does not publish a boundary-store HEAD or grant model execution. The old v1
entrypoints and static layouts retain their prior behavior and reject dynamic
owners. Production, GPU, vertical windows and active-event resume are excluded.

The source prototype is based on committed MASY
`9c36078fb6b81c02287334b7747a45cc1822a432`, MAPLE
`89a2775f84d80684f4a4effbb6b131b1850e0d2e` and SYRUP
`d05d8c6c66d9fd2969c007681916254e8d1c2c7c`. Its edited source manifest is a
separate controlling identity. Historical CPU locks are native/environment
references, never locks for these edited wrapper bytes.

## Original inputs and one owning decode

`capture_original_inputs_v2`, `save_original_inputs_v2` and
`load_original_inputs_v2` use `masy.dense_original_inputs.v2`. The full canonical
future plan remains in the existing `static_parts.vegetation_profile` role.
`vegetation_limits` separately seals the original typed plan's 15 bounded integer
controls. The loader checks raw size, metadata, source identity and those controls
before numerical payload expansion and native typed factories. It returns one
private decoded carrier containing the original inputs and their genuine typed
plan. That exact plan owns both endpoint loads; a second decoded plan is not
substituted during restoration.

## One native physical authority

`pack_boundary_physical_v2` and `load_boundary_physical_v2` use the unchanged
MAPLE `maple-exact-physical-checkpoint/1` codec. `masy.dense_boundary_physical.v2`
is the wrapper identity sealed inside that native format. The native payload
already contains all five vegetation arrays. No vegetation array sidecar is
introduced, no bed is rebuilt from elevation, and no accepted delta is replayed.

The genesis request contains the actual original capsule, owning plan, complete
empty native clock and expected independent metadata seal. Its initial vegetation
ticket is created only from the genuine native loader return. The current request
must use that ticket from the same owning decode, the complete accepted clock and
the saved envelope. The envelope is installed before bed verification. The
restored bed retains the actual initial and current native objects by reference.
These private Python tickets establish an internal call discipline; they are not
a Python security boundary.

## Passive runner image

`save_passive_boundary_v2` and `prepare_passive_boundary_v2` use
`masy.dense_runner_boundary.v2` and a distinct inert `_PreparedBoundaryV2`.
The loader prepares exactly 28 runner fields, including the original plan and
accepted vegetation copy counter. It never calls the runner constructor, native
initialization, transport, commit, reset or vegetation-update preparation.

The ten-key `masy.dense_shared_resources.v2` record binds the full envelope,
independent metadata seal, current soil digest, prescribed-input identity and
accepted copy counter. Every event body must agree with the envelope's exact
delta receipts and complete binding history. Cursor, accepted-body count, native
clock count and envelope boundary count must agree, including an empty history.
The default-flat copy counter is exactly
`48*cells + 8*cells*accepted_rain_events + sum(delta_receipt.copied_bytes)`.

Original water inputs remain original. A temporary water probe uses the current
owned cover, calls the genuine runner water validator, compares its returned
initial-soil copy with original initial soil, then discards it. The accepted
current soil comes from the runner image, retaining the native zero-soil dry
reset. The probe has at most three cell-shaped float64 arrays, `24*cells` bytes
total (`16*cells` additional to the prior single-array probe). Nonempty
`WaterExchange` remains unsupported, including a named zero exchange.

Existing native conservation bounds, clocks, explicit returned elapsed values,
rerouting threshold and cache compatibility checks remain authoritative.
Vegetation restoration does not itself request a hydraulic reroute. No new
ecological law, coefficient, water-retention policy or numerical tolerance is
defined here.

## Bounds and qualification

The profile retains the existing limits: at most 64 cells, 6 classes, 16 voxels,
16000 flat cohort slots and 8 events. Original-input numeric/serialized/metadata
caps remain 64/72/4 MiB; wrapper caps remain 1/6/4 MiB, with fixed five or seven
arrays. Native physical loads remain at most 64 MiB each. All referenced child
raw sizes are admitted before hashing or expansion, with the existing 512 MiB
global raw limit and 2 GiB component data/readback reservation. The actual
current-cover probe charge is included before that reservation check. These
logical bounds are not a claim about total Python/JAX RSS; the separately admitted
small CPU worker must also enforce finite OS, host-headroom, disk and time limits.

The source-only delivery includes genuine constructor roundtrips and refusal
controls. Its separately named transport test requires an additional explicit
execution gate: actual wind-rain-wind-rain, manual increase/decrease, future
pending intent, exact accepted continuation comparison and late second-native-load
failure. Merely collecting or writing that test establishes no transport or
persisted-recovery acceptance.

Atomic boundary-store create/recover integration is a later named C-v2 task.
Every restart-referenced deep version must remain retained. This component does
not implement C publication, duplicate-acknowledgement recovery, garbage
collection or migration of old runtime/source identities.
