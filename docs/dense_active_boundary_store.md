# Opt-in active-water Dense boundary store

This new static CPU format keeps the original C store lock, atomic HEAD publisher,
Native water continuation and original physical/B checkpoint owners. It is a
Source candidate until separately qualified against a genuine new immutable
MASY runtime. It does not migrate an ordinary v1/v2 store.

Create through `dense_boundary_store.create_active_water_boundary_store` with an
untouched genuine static Dense runner, its independently captured original
inputs, the actual runtime reference and the existing storage declarations.
The new schema is `masy.dense_boundary_store.activewater.v1`; its profile is
`default_dense_numpy_activewater_v1`. All original default create/recover APIs
and dynamic vegetation behavior keep their original paths.

`handle.checkpoint_water(parent_token, boundary_ordinal=n)` requests an existing
ORIGINAL native rain-plan boundary. It returns a prepared immutable ACK after
actual SAVE, original-writer P2, anchored LOAD/readback, context cleanup and HEAD
publication. Native completion wins if reached before the request. A checkpoint
request does not force completion or reset water. `handle.step(parent_token)`
finishes an active rain continuation through actual Native behavior or runs the
next ordinary event from the actual accepted bed. Limits/errors are incomplete.

Selected revision R and accepted event boundary A are distinct. A wet revision
advances R only. Accepted sequence, physical clock, receipts and accepted bed/soil
remain at A until genuine completion. Revision is bounded by24, accepted cursor
by8 and a chain by25. ORIGINAL boundary ordinal is separate from the unchanged
maximum of two wet pauses; an ordinal above2 is legitimate. Both source-family
and actual paused Native metadata are validated before cold use.

The managed `.masy-water-<store_id>` sibling is at its final canonical path from
creation. Its inode, parent and filesystem identities are part of STORE. It
shares C's exclusive lease, aggregate1GiB/4096-entry envelope, four-orphan limit
and1GiB/256-inode free reserves. Old referenced versions and failed attempts are
retained. No sealed child is moved, adopted from an orphan or garbage-collected.
Each actual Native child still has exactly its original three files; known
failed Native partial staging remains bounded and is never selected.

A request is fixed by the actual event operation, selected parent raw HEAD and
closed intent. A fresh attempt nonce is separate. The event operation remains
the original C operation derived from accepted A, original event index and
resolved schedule. ACK core has no circular token/hash dependency.
`handle.acknowledge(parent_token, request_kind=..., boundary_ordinal=...)`
looks up the direct selected child in validated ancestry. A repeated matching
request returns identical ACK/receipt with zero Native LOAD or transport.
An unpublished request is not declared consumed from an intent or file's
presence. A conflicting direct-child intent or unrelated token refuses.

Explicit recovery takes the externally pinned STORE file SHA. It validates the
exact selected HEAD and all referenced children, loads the accepted A through
real B and validates wet R by genuine anchored Native LOAD. It advances no rain,
wind, cursor, export, deposition, reset or clock. Temporary contexts are released
before returning the metadata facade. A private context that cannot close stays
guarded; failure does not claim an unchanged or reusable live attempt.

All fallible ACK construction, checks, Native SAVE/P2/LOAD, cleanup and directory
synchronization precede the unchanged C publisher. The publisher alone performs
its final HEAD replace/root-fsync. An uncertain result requires closing and
explicit recovery. Lost ACK after completed publication uses metadata lookup.
Python exception-fence tests do not establish process-death or hardware power
loss durability. Root must separately run the existing sequential primary-worker
process-death qualification at the documented fences; no new executor is added.

The logical reservation is original `C(L,W) + 2W + M_chain + M_context + future B
metadata + 2MiB`, under the SAME6GiB C cap. `M_chain` charges three possible
simultaneous chain-validation receiver families using stat-admitted raw sizes,
without alias credit. `M_context` enumerates original/proposed state records,
two genuine parents/selections, ACK/index/report records, bounded inventories
and a raw capsule. Each actual StageA/Native phase still enforces its original
work/P1/layout/reader/writer bounds. Wire bytes are not a whole-heap bound.
Unfit admission refuses; it never raises a cap or changes Native physics.
Actual interpreter/provider/compiled/source origins,8GiB process AS, CPU/wall,
free headroom and32MiB retained-stage qualification remain Root prerequisites.

The two new test Sources define meaningful metadata controls and genuine Tiny
pause/re-export/finish/recovery/default/IO-fence roles. Their Source counts are
predictions until Root's actual collect/freeze/check. Fresh writer and reader
are separate Root workers, with externally pinned actual expectation bytes.
No numerical/provider/test/model work was run during Source authoring.
