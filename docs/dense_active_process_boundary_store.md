This opt-in format preserves a genuine unfinished Native wind **or** water event beside its last accepted landscape. It is an implementation candidate awaiting a new complete immutable runtime and Root's separate numerical qualification. Existing static, dynamic and `activewater.v1` stores keep their formats; none is migrated automatically.

Use `dense_boundary_store.create_active_process_boundary_store` and `recover_active_process_boundary_store`. The format is `masy.dense_boundary_store.activeprocess.v1`, profile `default_dense_numpy_activeprocess_v1`. The existing `ActiveWaterAcknowledgement` immutable record is reused with the new schema; its historical Python class name is not a process tag.

The first profile is static prescribed vegetation, Dense host NumPy, default aerodynamic wind with dormancy explicitly OFF, flat mobile cohorts, regional/lognormal hop-distance routing and deposit-all impacts. Production/reduced/topographic/separation/wake/creep, GPU, windowed storage and evolving vegetation are excluded. Native natural commits remain Native decisions. No ecological response or soil-water law is added. Wind still requires the genuine `source_manifest_prototype` runtime kind and the exact Native/SYRUP Source-family tables already required by `dense_wind_pause`. A committed CPU lock does not silently become a wind prototype. A future current-pair composition and its environment/source/compiled qualification are prerequisites, not results of this Source change.

## Selected authority and exactly-once requests

Accepted cursor **A** counts completed original events. Revision **R** counts successful pauses and completions. At most two pauses per event and eight events give R<=24 and a selected chain of at most25 records. An unfinished pause changes R, not A, accepted elapsed time, accepted receipts or accepted bed. `active_ref` is a closed wind/water union with the actual ordinal, independent pause count, original plan hash, Native time and origin, attempt name and descriptor SHA. STORE binds the original event-kind list; creation derives it from the genuine runner, real accepted-parent reload compares it with the original schedule, and metadata chain validation checks paused process tags at A.

`checkpoint_wind(parent, boundary_ordinal=...)`, `checkpoint_water(...)` and `step(parent)` use the original C exclusive writer and publisher. The event operation ID is fixed by the store, accepted A, event index and schedule. Request identity additionally binds the exact selected raw R and intent; a fresh attempt nonce is not a new physical operation. Completion wins if Native finishes before the requested pause boundary. No pause forces a commit or finalizer.

Lost-ACK queries return the exact selected direct-child acknowledgment, without a Native LOAD or transport replay. A different direct-child request conflicts. An orphan cannot become selected success. Every referenced old child/deep version and failed attempt stays retained; there is no garbage collection or fallback to older HEAD.

## Wind child and cold binding

A wind child lives at the final code-owned `.masy-active-<store-id>/<generation>` sibling path. It contains `entry/capsule.json`, `native/continuation.bin`, and `export.json`. There is no wind `.native.partial-*` writer. The descriptor binds original path/inode/time/mode/hash observations; capsule and Native files are readonly. File and directory fsyncs finish before C publication. The existing C inventory admits every retained file before parser/hash work. The Native artifact is limited to8MiB before write, although Native's independent in-memory codec wire bound is larger. Oversize is refusal, not permission to change a limit.

Native's portable continuation codec alone serializes, validates and restores its graph, layout, aliases and flags. MASY adds C ancestry/custody and original entry facts; it does not parse that binary or copy the codec. Cold loading reconstructs the genuine accepted-A MASY stage, initial scheduler shell, original coverage plan and inventory through existing factories. `initial_scheduler_state` is passive; no Native begin/prologue/advance/finalizer/commit is called during this binding. Native restores its actual paused token. Exactly one public six-scalar progress call validates the saved pause, then MASY mints a fresh local lease. An exported or unpickled wrapper token is never authority.

At genuine Native completion only, the decoded prescribed vegetation/threshold objects are compared with the held accepted controls through actual Native validators, canonical exact raw equality, typed shape/dtype/backend/layout and unchanged flag/base observations. A new completed result shell substitutes exactly those two equal object references. Every other physical/state/result field retains identity. Paused graphs are never rebound; arrays, Native counters, clocks, accounting and caches are not modified. Ordinary `_wind_accept`, settlement, finalizer and adoption follow at their original points. Missing/mismatched controls halt truthfully.

Before any new HEAD is published, a second genuine accepted-A context restores the written wind child through the real Native codec/progress API. Both temporary contexts then abandon/close their actual paused owners. The unchanged C publisher receives a prepared ACK/state only after all readback, comparison, source checks, file/directory syncs and cleanup. Nothing new runs after its final root fsync.

Water uses the existing Native603 SAVE/P1 budget/original-writer P2 audit/anchored LOAD path. It retains its three Native files and genuine wet continuation/reset/clock/accounting rules. Finishing accepted wind passes the same evolved bed to water; finishing water passes the accepted dry state to wind. There is no fresh case/DEM reconstruction or mobile-load discard.

## Admission and failure limits

The original C logical6GiB, 1GiB store+sibling/4096 entries/four orphan attempts,1GiB+256inode free reserves, Native phase/W limits and all Source/environment/compiled checks remain enforced. Intended first qualification retains8GiB AS,120/135CPU,180wall,8MiB streams/files,32MiB stage,1024fds and9GiB host headroom. These are distinct limits, never a total-heap or elapsed-time fit promise.

The new Source reservation adds the actual Native typed codec capacities,3E+N overlapping byte/decoded roles, graph/planner/parser/reference/registry metadata, bounded closed writer-capture metadata, Source-observer headers and actual stat-sized reader metadata. Here E=min(native read cap,40+metadata cap+raw cap+32), N is the native raw cap. Both complete work/readback owners, old chains, original staging, finalizer/validation families, comparison receivers and failure frames remain independently charged. Existing Native per-family work/read caps are not an aggregate whole-heap budget. Repeated scan/source/codec call work and the outer process guards remain mandatory. Root must inspect the concrete resource ledger and qualify the actual small fixture; unsupported fit refuses before the allocation it would authorize.

Reader parser charges bind to the admitted file identity and exact length through the original no-follow/fstat/read/fstat reader, before decoding. A larger replacement cannot borrow a smaller file's admission. No Source/hash/path/kernel-result cache is added.

A pre-HEAD error retains old selected authority plus truthful unselected evidence. Unknown source/identity/Native/IO failures halt the facade. Genuine unretired Native owners keep the parent busy rather than claiming idle. Original C replace/fsync uncertainty remains `BoundaryStoreIndeterminate`; recovery examines exact selected HEAD, never an orphan. Post-acceptance lost-ACK cannot turn success into a second transport call.
