## Selected authority and exactly-once requests

Accepted cursor **A** counts completed original events. Revision **R** counts successful pauses and completions. At most two pauses per event and eight events give R<=24 and a selected chain of at most25 records. An unfinished pause changes R, not A, accepted elapsed time, accepted receipts or accepted bed. `active_ref` is a closed wind/water union with the actual ordinal, independent pause count, original plan hash, Native time and origin, attempt name and descriptor SHA. STORE binds the original event-kind list; creation derives it from the genuine runner, real accepted-parent reload compares it with the original schedule, and metadata chain validation checks paused process tags at A.

`checkpoint_wind(parent, boundary_ordinal=...)`, `checkpoint_water(...)` and `step(parent)` use the original C exclusive writer and publisher. The event operation ID is fixed by the store, accepted A, event index and schedule. Request identity additionally binds the exact selected raw R and intent; a fresh attempt nonce is not a new physical operation. Completion wins if Native finishes before the requested pause boundary. No pause forces a commit or finalizer.

Lost-ACK queries return the exact selected direct-child acknowledgment, without a Native LOAD or transport replay. A different direct-child request conflicts. An orphan cannot become selected success. Every referenced old child/deep version and failed attempt stays retained; there is no garbage collection or fallback to older HEAD.
