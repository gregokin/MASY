# Passive device physical checkpoint component

This isolated component is under source review. Positive device export and
resource qualification have not run. It is private and no default runner or CLI
selects it.

The proposed `dense_device_checkpoint` adapter exports the default six-class
Dense device owner's accepted bed, empty wind pool, five native vegetation
fields and threshold modifiers into owned, readonly NumPy arrays. It calls
MAPLE's unchanged exact physical checkpoint codec. Native physical time,
availability, pending ledger and commit state remain part of that payload.
The original CPU bed can be released after construction: the caller retains a
`DenseBoundaryInputs` static capsule. Projection and readback create no CPU bed.

The component checks native owner/mirror generations, pinned device and stream,
input bindings and accepted boundary identities. It preserves retained routing
and soil in the running owner; their payloads are excluded from this artifact.
Production wind, dynamic vegetation, windowed storage, active/stopped events
and unresolved native mobile sediment are outside this first profile. It
supports native raster vegetation; explicit plant-object rasterization is
refused in this component.

Native transfer-counter deltas and explicit host copies are separate evidence.
Packet checks, payload copies and mirror readback are counted. Owned host arrays
receive readonly flags; borrowed inputs keep their flags. The staged native
artifact is read back against its independently computed physical fingerprint.
Native uncertainty exceptions propagate, and failed destinations remain for
inspection. Combined `HEAD` publication belongs to a later store adapter.
An export record is bound to its issuing object and original digests. Copying
or replacing that record does not issue another export. This private nominal
protocol does not provide a security boundary within Python. Save and readback
require the exact limits used for export and rederive the admitted reservation.

Before native loading allocates numeric arrays, the native archive auditor
checks their field inventory and dtype/shape multiset against the independently
sealed projection using the actual native expected-field helpers.
Rank-0 member bytes across native payloads are capped in aggregate by the
metadata limit. The native loader still
performs its complete manifest, payload, field and conservation validation.
This prevents a different archive layout from expanding the planned readback.
The protected caller must keep that artifact private and quiescent across
header admission and native loading. This component supplies no file lock or
protection against a concurrent writer replacing its files.

The draft data reservation includes projection/readback lifetimes, leaf copy,
comparison and hashing scratch, native serialized buffers, NumPy ZIP buffers,
metadata and static inputs. Source-derived allocation/copy census and protected
worker admission remain required. These terms establish neither Python/RSS nor
GPU allocator peak or production fit. Caps are currently 64 cells, 64 logical
voxels, six classes, 16,000 cohorts and eight events.
Caps are joint ceilings; passing any one does not establish admission. The
initial filesystem profile requires meaningful free-inode reporting and
refuses zero reported free inodes. `CheckpointPublicationUncertain` derives
from `OSError`; callers must distinguish it before ordinary I/O failures and
must retain that destination without retry or cleanup.

CPU checks are explicitly CPU-origin codec/refusal contracts. One uses the
existing genuine native wind fixture to obtain a nonzero-time pending ledger.
They do not prove that positive CuPy export ran. Future GPU qualification needs
a fresh admitted source/runtime/device profile. Full device restore, current
soil/routing persistence and exactly-once atomic combined restart remain later
work. No growth, uptake, mortality or water-reset rule is added.
