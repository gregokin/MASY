# Passive Dense runner boundary prototype

This isolated source-manifest prototype seals a closed default Dense NumPy boundary
image and prepares an inert private owner. It does not publish a store HEAD or expose
an adopted runner. Real accepted-event continuation, GPU, production, windowed and
active-event restart require separate qualification and authorization.

`save_passive_boundary(path, runner, *, artifact_root, originals, genesis, physical,
source_identity, environment_sha256, limits=BoundaryImageLimits())` writes a new
exclusive immutable image. The three references name already sealed retained children.
`prepare_passive_boundary(path, *, artifact_root, expected_manifest_sha256,
expected_source_identity, expected_environment_sha256, limits=...)` returns a private
inert carrier with copied diagnostics only. Private nominal loader tickets are an
internal Python caller discipline, not a security or provenance boundary.

References have exactly format, relative_path, manifest_file_sha256 and identity.
Original format is `masy.dense_original_inputs.v1`; its identity is original content
SHA256. Physical format is actual MAPLE `maple-exact-physical-checkpoint/1`; identity
is the unchanged bridge22 native identity. Its caller has schema
`masy.dense_runner_boundary_native.v1`, source_identity, environment_sha256 and
static_sha256. All original fixtures must be authored under the complete candidate
runtime source identity from genesis. Sources cannot be rebound on load.

Original34 decodes original inputs once; native22/15 alone load current physical
state. Genesis is a retained read-only audit; identical genesis/current references
load once. No fresh bed, default runner construction, forced commit, reset, reroute,
transport or replay occurs during preparation. The current pool is exactly the
native-loaded mobile object. Current soil is independently loaded and original soil
stays original. Native pending ledger and commit cadence remain untouched.

The image has exactly5 raw C float64 NPY arrays: current soil and four cumulative
class totals. Retained routing adds source and velocity, for exactly7 arrays. Graph,
network and grid arrays are never serialized here. Existing native factories rebuild
one retained graph from the saved LAST ACTUAL hydraulic source, then full25/23/6-field
fingerprints and optional None values are checked. Three future rain-entry readers
support the private projection while preserving legacy statements and native commit
threshold/source semantics. They do not authorize a next event in this milestone.

ClockLedger, canonical unchanged receipts, exact original inventory, static identities,
cursor, budgets and native source bindings are checked before owner preparation.
Receipt verification only folds stored transfers to check totals; it does not repeat
any transfer. The shared-resource slot is exactly version0, static prescribed fields,
native dry-reset policy and an empty update cursor/list. No vegetation/soil response
law or update mechanism is introduced.

Hard ceilings:64 cells,6 classes,16 voxels,16000 flat cohorts,8 events; wrapper1MiB
numeric,4MiB metadata,6MiB raw,4096-byte NPY headers,7 files; receipts256KiB each/2MiB
aggregate; original34 own64MiB numeric/72MiB raw; each native child64MiB with its actual
archive slack; combined raw512MiB. Limits may only tighten. A conservative explicit
combined data/readback reservation is checked before expansion; outer test workers
use8GiB AS,90/120 CPU seconds,180 wall seconds and8MiB output. These are component
engineering limits, not measured scale or performance acceptance.

Reviewed original34 FD/no-follow/header/strict-JSON helpers are reused unchanged.
Actual native literal filenames use unchanged runtime file guards after ancestor and
all raw byte admission. Held ancestor/file identities and hashes are checked around
path-based native delegation. This assumes quiescent owned artifacts and is not a
descriptor-atomic hostile-writer reader. Existing artifacts and permissions are never
changed to make a read succeed. Unsupported layouts and unknown fields refuse.

Immutability is the sealed content contract, not protection against a same-user writer.
The exclusive directory is0700 and files0400. Actual bytes are read back before the
manifest hardlink seal, with no clobber/overwrite. Exceptions from the link syscall
onward report `BoundaryPublicationUncertain`; a visible seal may need inspection and
durability may be uncertain. An exact leftover own manifest hardlink is recoverable.
Failures preserve old children and orphan evidence. There is no automatic deletion,
rollback assumption, garbage collection, HEAD protocol or crash-exactly-once claim.

Caller-tightened BoundaryImageLimits apply to persistence/preparation IO only. The
three future entry readers use the fixed bounded64-cell/6-class/1MiB profile ceilings;
they add no limits field to the exact8-field projection or26-field private owner.
The runner's original native work/step limits are retained separately and unchanged.
A projection refusal raised across the entry commit preparation keeps its original
code and external-mutation guarantee; it is not reclassified as native transport failure.
