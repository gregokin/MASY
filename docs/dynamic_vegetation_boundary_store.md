# Dynamic manual vegetation accepted-boundary store

This prototype adds the explicit `create_dynamic_boundary_store` and
`recover_dynamic_boundary_store` entrypoints. It uses default flat NumPy wind,
the existing conservative water model, five native vegetation fields, a fixed
full manual-update plan, and empty `WaterExchange`. Production wind, device or
windowed storage and active-event restart remain refused. This source candidate
has no numerical qualification until its separate execution evidence is accepted.

The dynamic STORE profile is `dynamic_manual_dense_numpy_accepted_v1`.
Its OI artifact is the existing original-input v2 codec. Its wrapper image is
passive-boundary v2. Physical payloads remain actual MAPLE checkpoint/1 with the
existing dynamic physical identity. All eleven STORE keys, generation/intent/
HEAD/acknowledgement shapes, permanent lease, operation IDs, token rules and
atomic replace/fsync engine are shared with v1. Static entrypoints explicitly
refuse dynamic stores; dynamic entrypoints explicitly refuse static stores.

Original inputs retain the entire typed vegetation plan, including its future
manual intent, initial native vegetation, original water inputs and source
identity. Each accepted B image owns current native soil and references the
exact current physical checkpoint plus genuine genesis. The same plan and
current five-field native vegetation are installed into the shared landscape
before validation. Water continues to observe the current owned cover through
the existing runner seam. The original prescribed inputs and current soil are
different roles; native zero-soil dry reset is preserved. No vegetation, soil,
rainfall, wind, deposition, export or reset is replayed during recovery.

Recovery validates the entire selected ancestry and retains every referenced
native/deep version. It checks exact clock/receipt/binding/cursor/version/source/
plan/copy-counter prefixes, raw native header and payload references, current
soil identity and its bounded streamed NPY row. It then uses the actual B/OI and
native selected/current and genuine-genesis loaders. Intermediate vegetation
metadata seals are header/ref-bound provenance: their framing is not recomputed
in C and is not claimed to authenticate arbitrary attacker-controlled artifacts.
Every other envelope field must match the selected validated prefix/genesis.
The selected owner and genuine genesis receive the existing full real validation.

One `step(parent_token)` performs one actual private runner event. Preparation,
native save, original validation, B readback, owner comparison, complete history,
acknowledgement construction and final HEAD readback finish before publication.
The unchanged publication tail replaces HEAD, fsyncs the root and assigns a fully
prepared metadata-only state. An error leaves the prior accepted HEAD or reports
publication indeterminate; it never implies event completion. Repeating an old
accepted parent token returns the exact direct-child acknowledgement without
transport or manual updates. No fallback HEAD, migration or garbage collection
is introduced.

Admission preserves all original limits: at most64 cells, six classes,
16 voxels/column,16000 flat cohort slots, eight events,64 manual deltas and
eight deltas per boundary. Cache capacity remains1MiB. C disk/entry/raw/node/
header/string caps and6GiB logical memory ceiling remain unchanged. Dynamic
admission occurs before original/plan recapture and again with the actual
runner's native work budget. It adds all native-v2 validation frames, retained
history metadata, full-plan decodes, bounded hash/clock/header temporaries,
initial-vegetation/probe copies and a source-censused D4 factory envelope.
The successful step has five original decodes, at most eight native loads,
nine original-terrain and at most seven saved-source graph factories; genesis
has ten original-terrain factories. These are bootstrap validation costs, not
production-scale performance evidence.

The logical requested-payload formula is separate from Python heap, opaque
NumPy/library workspace and measured RSS. A later qualification controller must
enforce fresh host/disk headroom and finite OS address-space, CPU, wall, output
and file limits for the whole worker. It must bind the complete candidate and
runtime manifests and verify actual module/compiled origins before and after.
No historical committed lock or GPU profile is rebound to this prototype.

The new checks separate constructor/metadata/failure controls from the explicit
real four-event transport case. The latter compares uninterrupted native
wind/rain/wind/rain with persisted recovery after the first two events, including
manual increase/decrease and future prescribed intent, complete native clocks,
current soil, vegetation/copy identities, exactly-once acknowledgement and
ancestor-field corruption refusals. Qualification is bounded synthetic interface
evidence; no ecological response law or production calibration is added.
