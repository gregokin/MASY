# Small GPU windowed wind and water

This additive interface is a candidate for a bounded physical qualification of
one explicitly labelled synthetic 4×4 landscape, one grain class, six voxels and
a three-voxel resident window. It schedules wind, rain with genuine recession,
wind, and rain with genuine recession. Root must accept the Source, qualify its
new immutable runtime and run the affected checks before claiming completion.
No run result is asserted by this guide.

`DeviceWindowedBedOwner` holds the actual seven-field shared state and referenced
immutable deep versions. Its independently copied work state, accepted mirror
and prepared next state use Native device exchange sessions, not a reconstructed
DEM or full-depth bed copy. Pending HOST journals remain Native owners until
actual publication. Accepted boundaries must be published and preserve the
ledger reconciliation baseline, availability, ledger, water and physical bed.

`build_windowed_device_runner` requires an explicit `DeviceWindowedWindProfile`,
the actual Native record/component limits, water inputs and control, owner and
resource limits, and the separate Root-authenticated
`DeviceWaterQualificationBudget`. The original strict resource-proof lane stays
separate. An absent `commit_qualification_device_entry` API is an error before
runner resource copying. The entry and complete-event functions come from the
separately accepted SYRUP composition; their existence alone is not a completed
water-event qualification.

Both winds use actual production-reduced Native GPU records with topographic
FFT winds, separation, creep and avalanching, then exactly one actual Native
finalizer. The fresh scheduler preserves absolute time and the seventh baseline
while clearing derived wind caches. The selected Native reduced fixture settles
each step's load before its endpoint: a completed `already_empty` finalizer is
the truthful expected result. No airborne mass is injected to force settlement.
Water cannot begin after a refused or incomplete wind.

Both water events use the same evolving bed and the original MASY rain engine:
actual forced entry commit, Native reroute trigger and retained routing source,
actual SYRUP completion, class and water budgets, and documented Native dry
reset. Wind then starts with the returned empty pool and dry water. The native
maximum per-cell net displacement rule decides rerouting; MASY supplies no
replacement threshold. Initial time 7.25 seconds is supplied to genuine Native
constructors before transport. Native elapsed times, recession and event cursors
are retained by the existing clock ledger.

There is one owned prescribed `VegetationState` with all five canonical raster
fields. The labelled existing recipe authors height 0.5 m and cover 0.25; the
other three fields come from the actual Native constructor. Both wind and water
use that holder's exact cover object. No ecology or scientific default is added.

All four wrapper events and the independent sequential Native oracle share one
original attempt budget: 2 GiB active CuPy pool, sampled 5 GiB leader RSS,
sampled 9 GiB driver growth, sampled 512 MiB run storage, 64 MiB file limit,
4 MiB combined output, CPU 480/540 seconds and 600 wall seconds. Native HOST and
device availability checks, including safety fraction 0.5, remain active. There
is no per-event timeout, pool reset, prewarm allowance or extra oracle allowance.
Root must independently enforce and record the original process/device/source
controls. Sampling is distinct from hard allocator, CPU and file limits.

The new before-copy producer adds actual resident/auxiliary/pending/packet/cache
payloads, current and next copies, mirror, error and comparison roles, unchanged
resource-owner copies and HOST controls. It uses genuine Native copy-session
plans. These are known payloads only. Eleven external runtime roles, eight
primitive units and constructor allocation remain `None`. Every new summary and
receipt says `known_subset_only` and “bounded physical qualification; known
subset only; no allocation proof”. Neither free memory, successful guards nor
sampled peaks establish an opaque allocation bound or fit theorem.
