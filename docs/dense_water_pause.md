# Private static Dense CPU water pause

This component proposes in-memory water continuation for the exact small default
Dense NumPy profile. It has not been numerically qualified by its source delivery.
It persists no active state and creates no restart store. Root owns execution,
current-source qualification and publication. Modified-source component positives
need their own truthful source manifest or a new committed lock; the historical
7f0 lock does not certify the changed MASY package.

`pause_water(runner, runtime_reference=..., boundary_ordinal=...)` starts the next
rain once. It returns either an opaque process/thread-bound token at an original
unfinished native boundary, or the ordinary accepted/stop receipt. Ordinals are
one-based positions in the original native `plan_boundaries`; the final guard
position is refused. `resume_water(runner, token, boundary_ordinal=None)` consumes
that token and completes, or requests one later original position. At most two
wet pauses are supported. Invalid/foreign/stale tokens, changed source and bad
requests do not consume the valid lease. `abandon_water` halts the attempted rain
without depositing, committing, resetting or advancing the accepted boundary.
Callers serialize initial entry as they do ordinary DenseRunner calls. A live
lease is bound to its actual weak runner owner, PID, thread object and opaque
token by identity. It is an internal Python ownership contract, not a security
boundary against a caller modifying private attributes.

The first profile requires the exact26-field static default host runner,
checkpoint-compatible native control (`commit=True`, `force_final_commit=False`,
array hydraulics, bisection, upwind, dense phase metadata, no exchange history,
step publication), at most64 cells/6classes/16voxels/16000cohorts/8events,
4096 original report rows and10000 native steps. An event has at most4096 rain
intervals. These bounds refuse unsupported inputs before stage allocation;
they do not rewrite numerical controls, rainfall, forcing or physics.
Production, dynamic vegetation plans, device/windowed state, CSR/characteristic,
active wind and persisted active continuation are excluded. Their ordinary
previous APIs remain unchanged.

The wrapper prepares its original genuine DenseStage, inventory, soil work,
entry commit, retained source/graph and origin exactly once. It then calls
SYRUP's real `complete_event` with a bool-only original-boundary callback.
The callback retains only its scalar target. Native quiet-ready completion wins
over a pause and reaches the unchanged dry validation/accounting/`_finish` once.
A wet return must pass the exact source-derived21 native layouts (including the two original rainfall types), bounded raw
array/metadata walk, native checkpoint validator and accepted-state disjointness
before a token is issued. The walker streams exact dtype/shape/scalar bits and
array identity/flags/bytes; it is an in-memory mutation seal, not a checkpoint
codec. No checkpoint arrays are serialized or normalized.

While wet, the accepted bed, private pool/soil, cursor, ClockLedger, cumulative
budgets, receipts, static vegetation and dry-reset policy remain at their prior
accepted boundary. `step`, `run` and the public `active_evidence` property refuse
before the old exception handler can replace the lease. Existing passive
checkpoint admission already refuses non-None active evidence. Accepted-state
readers still describe the accepted owner. Native mutable progress never appears
in the token or a public successful response.

Resume validates original entry, static/source/environment/accepted/private
identities and the full private wet result before consuming the token. It marks
BUSY and destroys the old token before the native call. It passes the actual
`continuation.result.state` and complete prior progress with the original
schedule/control/policy/report bounds; it does not repeat entry, stage creation,
entry commit, rainfall, routing construction, final settlement or reset. It uses
actual native rerouting and configured thresholds, retaining the last actual
water source. Native clocks stay unchanged; realized intervals are compared with
the actual uninterrupted same-case oracle, never historical recession endpoints.

A native/validation failure after consumption halts the attempt. `_Stop` from
accepted-state or work-cap prechecks becomes the ordinary truthful stop receipt;
external mutation uses the original external-change guarantee. The last validated
paused time is not presented as the unknown end of a failed continuation.
A failure/interruption during final adoption explicitly reports possible partial
publication and permanently halts; no rollback is assumed. If acceptance already
finished, a lost acknowledgement is re-raised without manufacturing a failed
event. Allocation failure during stop construction still leaves the preallocated
BUSY/HALTED refusal. Closing/halting drops this lease's stage/progress references;
it cannot release independent caller references or retained exception tracebacks.

Resource admission is source-bound after the unchanged owning runtime binding.
It refuses native bodies outside the audited MAPLE bundle/SYRUP source digest.
The reservation separately charges accepted/static owners, the original stage
and complete retained entry commit/callback objects, prior and new full71-field
results, old/new report prefixes, native eight-bed plus four avalanche-callback
generations, exchange/commit
copies, array-hydrology/wet-law/upwind/dense/validator temporaries, bounded logs
and metadata. It deliberately overreserves Python-visible expression outputs
from59 complete owning source files, including inactive branches. Arrays appended
to log/history are excluded by the admitted profile; source-visible accumulated
reports/logs and replacement loops are counted explicitly. This source bound is
not a heap peak, import/NumPy-private allocator/JIT estimate or fit measurement.
A separate finite whole-worker AS/RSS/CPU/wall/host-headroom gate is mandatory.
The component neither sets process limits nor queries a device.
